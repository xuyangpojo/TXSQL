# SQL优化器优化开发方向指南

本文档说明可以从哪些方面入手对TXSQL优化器进行优化开发。

## 一、优化器架构概览

TXSQL优化器主要包含以下组件：

1. **查询重写器** (`sql/sql_optimizer.cc`)
2. **连接顺序优化器** (`sql/sql_planner.cc` - 贪心算法)
3. **Hypergraph优化器** (`sql/join_optimizer/` - 新算法)
4. **范围优化器** (`sql/range_optimizer/`)
5. **成本模型** (`sql/opt_costmodel.cc`)
6. **统计信息** (`sql/opt_statistics.cc`)

---

## 二、主要优化方向

### 1. 连接顺序优化 ⭐⭐⭐⭐⭐

**位置**: `sql/sql_planner.cc`

**当前算法**: 贪心算法（`greedy_search`）

**优化方向**:

#### A. 改进贪心算法
- **文件**: `sql/sql_planner.cc::Optimize_table_order::greedy_search()`
- **问题**: 贪心算法可能陷入局部最优
- **改进方案**:
  1. 增加多起点搜索（从不同表开始）
  2. 使用beam search（保留多个候选）
  3. 添加回溯机制

```cpp
// 当前代码位置
bool Optimize_table_order::greedy_search(uint search_depth) {
    // 可以改进：尝试多个起始表
    // 可以改进：保留top-k候选而不是只保留最优
}
```

#### B. 实现动态规划
- **文件**: `sql/sql_planner.cc`
- **优势**: 保证全局最优（对于小规模查询）
- **实现思路**:
  1. 使用DP表存储子集的最优成本
  2. 状态：`dp[mask] = 最优成本`，mask是表的位图
  3. 转移：`dp[mask] = min(dp[submask] + join_cost(...))`

#### C. 使用Hypergraph优化器
- **文件**: `sql/join_optimizer/join_optimizer.cc`
- **优势**: 支持更复杂的连接图（如星型、链式）
- **当前状态**: 已实现，但功能有限
- **改进方向**:
  1. 改进子图枚举算法
  2. 优化成本估算
  3. 支持更多连接类型

## 三、推荐的开发顺序

### 阶段1: 成本模型调优（最容易，影响大）⭐⭐⭐⭐⭐

1. **调整成本常量**
   - 文件: `sql/opt_costconstants.cc`
   - 方法: 运行基准测试，调整常量使估算更准确
   - 预期效果: 10-30%性能提升

2. **改进页读取成本**
   - 文件: `sql/opt_costmodel.cc::page_read_cost()`
   - 方法: 考虑缓存命中率、顺序vs随机
   - 预期效果: 5-15%性能提升

### 阶段2: 连接顺序优化（中等难度，影响大）⭐⭐⭐⭐

1. **改进贪心算法**
   - 文件: `sql/sql_planner.cc::greedy_search()`
   - 方法: 多起点搜索、beam search
   - 预期效果: 5-20%性能提升

2. **实现动态规划（小规模查询）**
   - 文件: `sql/sql_planner.cc`
   - 方法: 实现DP算法，限制表数量（<10）
   - 预期效果: 10-30%性能提升（小查询）

### 阶段3: 索引选择优化（中等难度）⭐⭐⭐

1. **改进索引选择**
   - 文件: `sql/sql_planner.cc::best_access_path()`
   - 方法: 考虑覆盖索引、索引合并
   - 预期效果: 5-15%性能提升

2. **利用直方图**
   - 文件: `sql/opt_statistics.cc`
   - 方法: 使用直方图改进选择性估算
   - 预期效果: 10-25%性能提升

### 阶段4: 高级优化（难度大）⭐⭐

1. **Hypergraph优化器改进**
   - 文件: `sql/join_optimizer/`
   - 方法: 改进子图枚举、成本估算
   - 预期效果: 15-40%性能提升（复杂查询）

2. **子查询优化**
   - 文件: `sql/sql_optimizer.cc`
   - 方法: 更智能的转换策略
   - 预期效果: 10-30%性能提升（含子查询）
