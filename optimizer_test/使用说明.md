# SQL优化器测试框架 - 完整使用说明

## 一、文件说明

### 核心程序文件

1. **`optimizer_test.cpp`** - 完全独立的测试程序
   - 不依赖原项目代码
   - 自己实现所有逻辑
   - 适合快速测试和理解

2. **`optimizer_with_real_code.cpp`** - 使用真实优化器逻辑的测试程序 ⭐推荐
   - 提取并使用了MySQL优化器的核心算法
   - 成本模型基于 `opt_costmodel.cc`
   - 连接顺序优化基于 `sql_planner.cc` 的贪心算法
   - 包含性能数据收集功能

3. **`test_data_generator.cpp`** - 测试数据生成器
   - 生成模拟的数据库表数据（CSV格式）
   - 生成统计信息文件
   - 生成测试SQL查询

### 文档文件

4. **`优化器优化方向.md`** - 优化开发指南
   - 详细的优化方向说明
   - 代码修改点
   - 推荐开发顺序

5. **`性能数据收集方法.md`** - 性能数据收集指南
   - 多种数据收集方法
   - 分析脚本示例
   - 基准测试方法

6. **`README.md`** - 基础使用说明
7. **`快速开始.md`** - 快速上手指南
8. **`代码依赖说明.md`** - 代码依赖关系
9. **`删除指南.md`** - 清理不需要的文件

## 二、快速开始

### 步骤1: 编译测试程序

```bash
cd C:\projects\TXSQL\optimizer_test

# 编译（使用真实逻辑的版本）
g++ -std=c++11 optimizer_with_real_code.cpp -o optimizer_test.exe

# 运行
./optimizer_test.exe
```

### 步骤2: 生成测试数据（可选）

```bash
# 编译数据生成器
g++ -std=c++11 test_data_generator.cpp -o data_generator.exe

# 运行（生成默认规模的数据）
./data_generator.exe

# 或指定数据规模
./data_generator.exe 50000 1000000 10000 5000000
# 参数：customers, orders, products, order_items
```

### 步骤3: 查看结果

程序会输出：
- 每个测试用例的执行计划
- 性能统计数据
- CSV格式的性能数据文件（`optimizer_performance.csv`）

## 三、使用真实优化器逻辑的优势

### 1. 成本模型基于真实代码

```cpp
// 这些常量来自 sql/opt_costconstants.h
constexpr double ROW_EVALUATE_COST = 0.2;
constexpr double KEY_COMPARE_COST = 0.1;
constexpr double IO_BLOCK_READ_COST = 1.0;
constexpr double MEMORY_BLOCK_READ_COST = 0.25;
```

### 2. 算法逻辑一致

- **连接顺序优化**: 基于 `sql/sql_planner.cc::greedy_search()`
- **访问路径选择**: 基于 `sql/sql_planner.cc::best_access_path()`
- **成本计算**: 基于 `sql/opt_costmodel.cc`

### 3. 可以调优成本常量

```cpp
CostModel cost_model;
cost_model.set_row_evaluate_cost(0.15);  // 调整行评估成本
cost_model.set_io_block_read_cost(0.8);  // 调整I/O成本
```

## 四、优化开发流程

### 阶段1: 理解当前逻辑

1. 阅读 `优化器优化方向.md`
2. 运行测试程序，观察当前行为
3. 分析性能数据

### 阶段2: 选择优化方向

推荐顺序：
1. **成本模型调优**（最容易，影响大）
2. **连接顺序优化**（中等难度，影响大）
3. **索引选择优化**（中等难度）
4. **高级优化**（难度大）

### 阶段3: 实现优化

1. 修改 `optimizer_with_real_code.cpp` 中的相应部分
2. 运行测试，对比优化前后
3. 分析性能数据

### 阶段4: 应用到真实代码

1. 在 `sql/sql_planner.cc` 或相关文件中实现
2. 编译完整项目
3. 使用真实数据库测试

## 九、常见问题

### Q: 为什么成本值看起来很大？
A: 成本是相对值，用于比较不同执行计划。绝对值不重要，重要的是相对大小。

### Q: 如何验证优化效果？
A: 
1. 运行优化前后的测试
2. 对比总成本
3. 对比优化时间
4. 如果有真实数据库，对比实际执行时间

### Q: 可以用于生产环境吗？
A: 这个测试程序主要用于：
- 理解优化器逻辑
- 实验优化方案
- 性能测试

生产环境应使用完整的MySQL/TXSQL。

### Q: 如何添加新的优化策略？
A: 
1. 在 `JoinOrderOptimizer` 中添加新方法
2. 实现新的算法（如动态规划）
3. 在 `optimize_join_order()` 中调用
4. 对比效果
